# الجلسة الأولى: تنصيب بيئة Flutter

## معلومات الجلسة

- المدة المقترحة: 150-180 دقيقة.
- الهدف العملي: يصل كل طالب إلى نتيجة مقبولة من `flutter doctor` وينشئ مشروعًا تجريبيًا.
- لا يُفترض وجود معرفة سابقة بـFlutter.

## أهداف التعلّم

بنهاية الجلسة يستطيع الطالب أن:

- يشرح الفرق بين Flutter وDart وVS Code وAndroid Studio بصورة بسيطة.
- يعرف وظيفة Flutter SDK وAndroid SDK والمحاكي.
- يستخدم الطرفية لتنفيذ أوامر بسيطة.
- يشغّل `flutter doctor` ويقرأ العلامات الأساسية.
- ينشئ تطبيق Flutter ويشغّله على جهاز أو محاكي.

## قبل بدء الجلسة

1. أرسل روابط التنزيل الرسمية قبل الجلسة.
2. اطلب من الطلاب إحضار الشاحن ووجود مساحة فارغة كافية.
3. جهّز نسخًا محلية من Flutter SDK عند ضعف الإنترنت.
4. لا تجعل VPN جزءًا إلزاميًا من Flutter؛ يُستخدم فقط إذا كانت خدمة مطلوبة محجوبة في بلد الطالب ووفق القوانين المحلية.
5. تأكد من تفعيل Virtualization لمن سيستخدم المحاكي.

## التشبيه الرئيسي

قل للطلاب: «صناعة تطبيق تشبه ورشة بناء».

| الأداة | التشبيه | الوظيفة الحقيقية |
|---|---|---|
| Dart | اللغة التي نتحدث بها | لغة كتابة الكود |
| Flutter SDK | صندوق الأدوات | مكتبات وأوامر بناء التطبيق |
| VS Code | طاولة العمل | محرر نكتب فيه الكود |
| Android Studio | مستودع أدوات Android | Android SDK والمحاكي |
| Git | دفتر تاريخ المشروع | يتتبع تغييرات الكود |
| الهاتف/المحاكي | مكان التجربة | يعرض التطبيق ويختبره |

وضّح أن VS Code لا يبني التطبيق وحده، وAndroid Studio ليس Flutter نفسه.

## تسلسل الشرح

### 1. ما هو التطبيق؟ وما هو Flutter؟ — 15 دقيقة

ابدأ بسؤال: «إذا أردنا إنشاء التطبيق نفسه لأندرويد وآيفون، هل نكتب مشروعين؟»

اشرح أن Flutter يساعدنا على بناء واجهات لعدة منصات من قاعدة كود واحدة. لا تدخل في تفاصيل المحرك أو الرسم الآن.

### 2. التعرف إلى الطرفية — 15 دقيقة

افتح الطرفية واشرح:

- الأمر هو طلب مكتوب للحاسوب.
- نكتب الأمر ثم نضغط Enter.
- الخطأ ليس كارثة؛ هو رسالة تساعدنا.

نفّذ `flutter --version` ثم اسأل: ما المعلومات التي ظهرت؟

### 3. تثبيت Git — 15 دقيقة

اشرح أن Git يحفظ تاريخ التعديلات، وأن بعض الأدوات تستخدمه لجلب مكونات. تحقق باستخدام:

```text
git --version
```

لا تدخل في GitHub أو الفروع في هذه الجلسة.

### 4. تثبيت Flutter SDK وإضافة PATH — 35 دقيقة

اشرح PATH كـ«قائمة عناوين يبحث فيها الحاسوب عن الأوامر». إذا لم نضف مجلد `bin` فلن يعرف الجهاز أين يجد أمر `flutter`.

بعد فك الضغط، لا تضع Flutter داخل مجلد يحتاج صلاحيات مدير أو داخل مسار يحتوي مشكلات مزامنة. نفّذ:

```text
flutter --version
```

إذا لم يُعرف الأمر، أغلق الطرفية وافتحها من جديد ثم راجع PATH.

### 5. VS Code والإضافات — 15 دقيقة

ثبّت إضافتي Flutter وDart من سوق إضافات VS Code. وضّح أن إضافة Flutter تجلب إضافة Dart تلقائيًا غالبًا، لكننا نتحقق من وجودهما.

### 6. Android Studio وAndroid SDK — 35 دقيقة

اشرح الفرق بين البرنامج وSDK والمحاكي. افتح SDK Manager وتحقق من:

- Android SDK Platform حديث ومدعوم.
- Android SDK Build-Tools.
- Android SDK Platform-Tools.
- Android Emulator عند استخدام محاكي.

لا تفرض رقم إصدار ثابتًا في المنهاج؛ الإصدارات تتغير.

### 7. `flutter doctor` — 20 دقيقة

اقرأ النتائج مع الطلاب:

- `[✓]` جاهز.
- `[!]` تنبيه يحتاج مراجعة.
- `[✗]` مشكلة تمنع جزءًا من العمل.

نفّذ أمر قبول تراخيص Android الذي يقترحه Flutter عند الحاجة، واقرأ كل سؤال قبل الموافقة.

نبّه: تحذير Visual Studio يتعلق عادةً بتطبيقات Windows desktop، وليس VS Code. إذا كان هدف الدورة Android فقط، فقد لا يمنع المتابعة.

### 8. أول تشغيل — 30 دقيقة

أنشئ المشروع من VS Code أو باستخدام الأوامر الموجودة في ملف الكود. افتح التطبيق الافتراضي، شغّله، ثم غيّر نصًا واحدًا واستخدم Hot Reload. الهدف هنا إثبات أن البيئة تعمل، لا شرح بنية الكود.

## أسئلة تحقق

- ما الفرق بين Flutter SDK وVS Code؟
- لماذا نضيف `bin` إلى PATH؟
- هل كل تحذير في `flutter doctor` يمنعنا من بناء تطبيق Android؟
- أين سيظهر تطبيقنا: في VS Code أم على هاتف/محاكي؟

## أخطاء متوقعة

| المشكلة | السبب الشائع | المعالجة التعليمية |
|---|---|---|
| `flutter` غير معروف | PATH خاطئ أو الطرفية قديمة | راجع المسار وافتح طرفية جديدة |
| لا يظهر الهاتف | USB debugging أو التعريف | جرّب `flutter devices` وراجع إعداد الهاتف |
| المحاكي بطيء | Virtualization غير مفعلة أو RAM قليلة | استخدم هاتفًا حقيقيًا إن أمكن |
| تراخيص Android ناقصة | لم تُقبل التراخيص | اتبع الأمر المقترح في `flutter doctor` |
| التنزيل بطيء | شبكة ضعيفة | استخدم ملفات مجهزة مسبقًا بدل إضاعة الجلسة |

## تذكرة الخروج

اطلب من كل طالب تصوير أو نسخ:

1. نتيجة `flutter --version`.
2. اسم الجهاز الظاهر في `flutter devices`.
3. صورة التطبيق الافتراضي وهو يعمل.
