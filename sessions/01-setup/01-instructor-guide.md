# الجلسة الأولى: تنصيب بيئة Flutter

## معلومات الجلسة

- المدة المقترحة: 150-180 دقيقة.
- الهدف العملي: يصل كل طالب إلى نتيجة مقبولة من `flutter doctor` وينشئ مشروعًا تجريبيًا.
- لا يُفترض وجود معرفة سابقة بـFlutter.

## أهداف التعلّم

بنهاية الجلسة يستطيع الطالب أن:

- يشرح الفرق بين Flutter وDart وVS Code وAndroid Studio بصورة بسيطة.
- يعرف وظيفة Flutter SDK وAndroid SDK والمحاكي.
- يستخدم الطرفية لتنفيذ أوامر بسيطة.
- يشغّل `flutter doctor` ويقرأ العلامات الأساسية.
- ينشئ تطبيق Flutter ويشغّله على جهاز أو محاكي.

## قبل بدء الجلسة

1. أرسل روابط التنزيل الرسمية قبل الجلسة.
2. اطلب من الطلاب إحضار الشاحن ووجود مساحة فارغة كافية.
3. جهّز نسخًا محلية من Flutter SDK عند ضعف الإنترنت.
4. لا تجعل VPN جزءًا إلزاميًا من Flutter؛ يُستخدم فقط إذا كانت خدمة مطلوبة محجوبة في بلد الطالب ووفق القوانين المحلية.
5. تأكد من تفعيل Virtualization لمن سيستخدم المحاكي.

## شرح جاهز: ما الفرق بين الأدوات؟

يمكنك البدء بالنص التالي:

> قبل أن نثبت أي برنامج، نريد أن نعرف لماذا نحتاجه. عندما نصنع تطبيقًا فنحن لا نستخدم برنامجًا واحدًا يقوم بكل شيء. نحتاج لغة نكتب بها التعليمات، وأدوات تحول هذه التعليمات إلى تطبيق، ومحررًا يساعدنا على الكتابة، وأدوات خاصة بالنظام الذي سيعمل عليه التطبيق.

### Dart

> Dart هي لغة البرمجة التي سنكتب بها أغلب تعليماتنا. مثلما نتحدث مع شخص بالعربية أو الإنجليزية، نتحدث مع الحاسوب بلغة لها كلمات وقواعد محددة. سنكتب في Dart متغيرات وشروطًا ودوال، ثم يستخدم Flutter هذا الكود لبناء التطبيق.

مثال لا يحتاج إلى تشغيل:

```dart
String name = 'Lina';
print('Hello $name');
```

اشرح أن السطر الأول يخزن اسمًا، والثاني يطلب طباعة رسالة. لا تدخل الآن في تفاصيل الأنواع.

### Flutter وFlutter SDK

> Flutter هو إطار عمل يساعدنا على بناء واجهة التطبيق: النصوص والأزرار والصور والشاشات. أما Flutter SDK فهو الحزمة التي ننزلها على الجهاز، وتحتوي الأوامر والمكتبات والأدوات التي يحتاجها Flutter. كلمة SDK اختصار لـSoftware Development Kit، ومعناها «حزمة أدوات تطوير البرامج».

داخل Flutter SDK توجد أشياء مثل:

- أمر `flutter` الذي ننفذه من الطرفية.
- مكتبات Widgets الجاهزة.
- أدوات إنشاء المشروع وفحص البيئة وبناء التطبيق.
- نسخة من Dart SDK مناسبة لنسخة Flutter.

للمدرّس: Flutter ليس لغة برمجة. اللغة هي Dart، وFlutter يستخدم Dart.

### Android SDK

> Android SDK حزمة مختلفة، أعدتها Google للتعامل مع نظام Android نفسه. Flutter يعرف كيف يبني الواجهة، لكنه عندما يريد إخراج تطبيق Android يحتاج أدوات Android لتحويل المشروع إلى تطبيق يستطيع الهاتف تثبيته وتشغيله.

يحتوي Android SDK على:

- أدوات بناء تطبيق Android.
- أدوات التواصل مع الهاتف مثل `adb`.
- ملفات المنصات الخاصة بإصدارات Android.
- أدوات المحاكي عند استخدام جهاز افتراضي.

### الفرق بين Flutter SDK وAndroid SDK

قل بوضوح:

> Flutter SDK يعطينا أدوات Flutter العامة التي نستخدمها لكتابة مشروع يمكن أن يستهدف أكثر من منصة. Android SDK يعطينا أدوات خاصة بمنصة Android. إذا شبّهنا التطبيق برسمة نريد طباعتها، فـFlutter يساعدنا على تصميم الرسمة، وأدوات Android تجهز النسخة المناسبة لطابعة Android.

| السؤال | Flutter SDK | Android SDK |
|---|---|---|
| من يوفره؟ | فريق Flutter | Google/Android |
| ما وظيفته؟ | إنشاء وتشغيل وبناء مشاريع Flutter | بناء وتشغيل واختبار تطبيقات Android |
| هل يحتوي Widgets؟ | نعم | ليس Widgets الخاصة بـFlutter |
| هل نحتاجه لتطبيق Android؟ | نعم | نعم |
| هل نحتاج Android SDK لتشغيل Flutter Web فقط؟ | لا عادةً | لا |

سؤال تحقق: «إذا ثبتنا Flutter SDK فقط ولم نثبت Android SDK، هل نستطيع كتابة الكود؟»

الجواب: نعم نستطيع كتابة كود Flutter، لكننا لن نملك سلسلة أدوات Android اللازمة لبناء وتشغيل نسخة Android.

### VS Code

> VS Code هو محرر كود. يشبه دفترًا ذكيًا: يلون الكلمات، يقترح تكملة الكود، ويظهر بعض الأخطاء ويسمح بتشغيل الأوامر. لكنه ليس Flutter ولا يحول الكود إلى تطبيق وحده؛ هو واجهة مريحة تستخدم الأدوات المثبتة على الجهاز.

### Android Studio

> Android Studio بيئة تطوير كاملة لتطبيقات Android. في هذه الدورة قد نكتب الكود داخل VS Code، لكننا نستفيد من Android Studio لتثبيت وإدارة Android SDK وإنشاء المحاكي.

### الفرق بين Android Studio وAndroid SDK

> Android Studio برنامج له نوافذ وقوائم ومحرر. Android SDK مجموعة أدوات وملفات تستخدم في الخلفية. يمكن تشبيه Android Studio بورشة لها باب ولوحات تحكم، وAndroid SDK بالآلات الموجودة داخل الورشة.

### الفرق بين VS Code وVisual Studio

> VS Code محرر خفيف سنستخدمه لكتابة Flutter. Visual Studio برنامج آخر من Microsoft يُستخدم، من ضمن استخداماته، لتوفير أدوات بناء تطبيقات Windows المكتبية. لذلك قد يقول `flutter doctor` إن Visual Studio غير موجود، مع أن VS Code مثبت. إذا كانت دورتنا تستهدف Android فقط، فهذا التحذير لا يمنعنا عادةً.

### Git وGitHub

> Git برنامج يحفظ تاريخ تغييرات المشروع على جهازنا: ماذا تغير ومتى، ويسمح بالرجوع والمشاركة. GitHub موقع يستضيف مستودعات Git على الإنترنت. إذًا Git هو الأداة، وGitHub خدمة يمكن أن نرفع إليها المشروع.

### الهاتف الحقيقي والمحاكي

> الهاتف الحقيقي جهاز فعلي نجرب عليه التطبيق. المحاكي برنامج يقلد هاتف Android داخل الحاسوب. كلاهما هدف تشغيل؛ أي المكان الذي سنشاهد عليه التطبيق.

## التشبيه الرئيسي

قل للطلاب: «صناعة تطبيق تشبه ورشة بناء».

| الأداة | التشبيه | الوظيفة الحقيقية |
|---|---|---|
| Dart | اللغة التي نتحدث بها | لغة كتابة الكود |
| Flutter SDK | صندوق الأدوات | مكتبات وأوامر بناء التطبيق |
| VS Code | طاولة العمل | محرر نكتب فيه الكود |
| Android Studio | مستودع أدوات Android | Android SDK والمحاكي |
| Git | دفتر تاريخ المشروع | يتتبع تغييرات الكود |
| الهاتف/المحاكي | مكان التجربة | يعرض التطبيق ويختبره |

وضّح أن VS Code لا يبني التطبيق وحده، وAndroid Studio ليس Flutter نفسه.

## تسلسل الشرح

### 1. ما هو التطبيق؟ وما هو Flutter؟ — 15 دقيقة

ابدأ بسؤال: «إذا أردنا إنشاء التطبيق نفسه لأندرويد وآيفون، هل نكتب مشروعين؟»

ثم قل:

> يمكن كتابة تطبيق منفصل لكل نظام، لكن هذا يعني وقتًا وجهدًا أكبر. Flutter يسمح لنا بكتابة جزء كبير من المشروع مرة واحدة بلغة Dart، ثم بناء نسخ تعمل على منصات مختلفة. هذا لا يعني أن كل منصة متطابقة تمامًا أو أننا لن نحتاج أي إعداد خاص بها، لكنه يقلل تكرار العمل كثيرًا.

وضّح أن «قاعدة كود واحدة» لا تعني زرًا سحريًا يلغي فهم Android وiOS، بل تعني مشاركة معظم منطق وواجهة المشروع.

### 2. التعرف إلى الطرفية — 15 دقيقة

افتح الطرفية واشرح:

> الطرفية نافذة نرسل من خلالها أوامر نصية. بدل أن نضغط عدة أزرار في القوائم، نكتب أمرًا واضحًا. الأمر لا يعمل بمجرد كتابته؛ يعمل عندما نضغط Enter. بعد التنفيذ يعطينا البرنامج نتيجة أو رسالة خطأ. رسالة الخطأ ليست عقوبة، بل وصف لما لم يستطع البرنامج فعله.

اشرح ثلاثة أجزاء:

- **المؤشر:** المكان الذي ستظهر فيه الكتابة.
- **الأمر:** مثل `flutter --version`.
- **المخرجات:** النص الذي يعيده البرنامج بعد التنفيذ.

نفّذ `flutter --version` ثم اسأل: ما المعلومات التي ظهرت؟

الجواب المتوقع: نسخة Flutter، قناة الإصدار غالبًا، نسخة Dart، وبعض معلومات الأدوات. ليس مطلوبًا حفظ الأرقام.

### 3. تثبيت Git — 15 دقيقة

قل:

> عندما نعدّل مشروعًا عشرات المرات قد نكسر شيئًا كان يعمل بالأمس. Git يسمح لنا بحفظ نقاط من تاريخ المشروع ومعرفة الملفات التي تغيرت. كما تستخدمه بعض أدوات التطوير لجلب مشاريع أو حزم من مستودعاتها. اليوم سنتأكد فقط من تثبيته، وسنتعلم أوامره في درس منفصل.

تحقق باستخدام:

```text
git --version
```

لا تدخل في GitHub أو الفروع في هذه الجلسة.

### 4. تثبيت Flutter SDK وإضافة PATH — 35 دقيقة

قل:

> بعد تنزيل Flutter SDK يصبح أمر `flutter` موجودًا داخل مجلد اسمه `bin`. لكن الطرفية لا تفتش كل ملفات الجهاز عندما نكتب أمرًا؛ هذا سيكون بطيئًا جدًا. بدلًا من ذلك لديها قائمة مسارات اسمها PATH. عندما نضيف مجلد `flutter/bin` إلى PATH نقول للنظام: «إذا كتب المستخدم اسم أمر، ابحث في هذا المجلد أيضًا».

مثال تشبيهي:

> تخيل عامل توصيل معه دفتر عناوين. وجود المنزل في المدينة لا يكفي؛ يجب أن يكون عنوانه معروفًا. Flutter موجود على القرص، وPATH يجعل عنوان أمره معروفًا للطرفية.

إذا سأل طالب لماذا نضيف `bin` تحديدًا: لأنه المجلد الذي يحتوي الملفات التنفيذية والأوامر، وليس لأن كل مجلد Flutter يجب إضافته.

بعد فك الضغط، لا تضع Flutter داخل مجلد يحتاج صلاحيات مدير أو داخل مسار يحتوي مشكلات مزامنة. نفّذ:

```text
flutter --version
```

إذا لم يُعرف الأمر، أغلق الطرفية وافتحها من جديد ثم راجع PATH.

### 5. VS Code والإضافات — 15 دقيقة

ثبّت إضافتي Flutter وDart من سوق إضافات VS Code. وضّح أن إضافة Flutter تجلب إضافة Dart تلقائيًا غالبًا، لكننا نتحقق من وجودهما.

قل:

> الإضافة ليست Flutter SDK بديلًا. هي تجعل VS Code يفهم ملفات Dart وFlutter: تقترح أسماء Widgets، تلون الكود، تساعد في التشغيل، وتعرض الأخطاء. إذا ثبتنا الإضافة ولم نثبت SDK فالمحرر يعرف شكل اللغة، لكنه لا يملك كل أدوات البناء والتشغيل.

### 6. Android Studio وAndroid SDK — 35 دقيقة

ابدأ بالشرح الجاهز الموجود في قسم الفرق بين الأدوات، ثم قل:

> سنفتح SDK Manager، ومعناه مدير حزم Android SDK. منه نختار الأدوات والمنصات التي يحتاجها البناء. رقم Android الذي نراه هنا ليس نسخة Flutter؛ هو إصدار منصة Android التي سنبني ونختبر عليها.

افتح SDK Manager وتحقق من:

- Android SDK Platform حديث ومدعوم.
- Android SDK Build-Tools.
- Android SDK Platform-Tools.
- Android Emulator عند استخدام محاكي.

لا تفرض رقم إصدار ثابتًا في المنهاج؛ الإصدارات تتغير.

### 7. `flutter doctor` — 20 دقيقة

اقرأ النتائج مع الطلاب:

- `[✓]` جاهز.
- `[!]` تنبيه يحتاج مراجعة.
- `[✗]` مشكلة تمنع جزءًا من العمل.

قل:

> `flutter doctor` لا يصلح كل شيء تلقائيًا. هو يفحص البيئة ويكتب تقريرًا. قد يكون في التقرير تحذير لا علاقة له بهدفنا الحالي، مثل أدوات Windows desktop، وقد يكون فيه خطأ مهم مثل غياب Android SDK. لذلك لا نعد العلامات فقط؛ نقرأ اسم كل قسم.

اقرأ الأقسام بهذه الطريقة:

1. **Flutter:** هل SDK نفسها معروفة؟
2. **Android toolchain:** هل أدوات Android والتراخيص جاهزة؟
3. **Connected device:** هل يوجد مكان نستطيع تشغيل التطبيق عليه؟
4. **Editor:** معلومات مساعدة عن المحررات.
5. **أدوات منصات أخرى:** نحتاجها فقط إذا كانت المنصة ضمن هدفنا.

نفّذ أمر قبول تراخيص Android الذي يقترحه Flutter عند الحاجة، واقرأ كل سؤال قبل الموافقة.

نبّه: تحذير Visual Studio يتعلق عادةً بتطبيقات Windows desktop، وليس VS Code. إذا كان هدف الدورة Android فقط، فقد لا يمنع المتابعة.

### 8. أول تشغيل — 30 دقيقة

أنشئ المشروع من VS Code أو باستخدام الأوامر الموجودة في ملف الكود. افتح التطبيق الافتراضي، شغّله، ثم غيّر نصًا واحدًا واستخدم Hot Reload. الهدف هنا إثبات أن البيئة تعمل، لا شرح بنية الكود.

قبل الأمر قل:

> `flutter create` ينشئ هيكل مشروع كاملًا: مجلدات للمنصات، ملف إعداد الحزم، ومجلد `lib` الذي سيحتوي معظم كود Dart الذي نكتبه. لا نحتاج فهم جميع المجلدات اليوم.

قبل `flutter run` قل:

> هذا الأمر يختار جهازًا متصلًا، يحول المشروع إلى نسخة مناسبة له، يثبت التطبيق ثم يشغله. أول تشغيل يكون أبطأ لأن أدوات كثيرة تُجهز للمرة الأولى.

## أسئلة تحقق

- ما الفرق بين Flutter SDK وVS Code؟
- لماذا نضيف `bin` إلى PATH؟
- هل كل تحذير في `flutter doctor` يمنعنا من بناء تطبيق Android؟
- أين سيظهر تطبيقنا: في VS Code أم على هاتف/محاكي؟

## أخطاء متوقعة

| المشكلة | السبب الشائع | المعالجة التعليمية |
|---|---|---|
| `flutter` غير معروف | PATH خاطئ أو الطرفية قديمة | راجع المسار وافتح طرفية جديدة |
| لا يظهر الهاتف | USB debugging أو التعريف | جرّب `flutter devices` وراجع إعداد الهاتف |
| المحاكي بطيء | Virtualization غير مفعلة أو RAM قليلة | استخدم هاتفًا حقيقيًا إن أمكن |
| تراخيص Android ناقصة | لم تُقبل التراخيص | اتبع الأمر المقترح في `flutter doctor` |
| التنزيل بطيء | شبكة ضعيفة | استخدم ملفات مجهزة مسبقًا بدل إضاعة الجلسة |

## تذكرة الخروج

اطلب من كل طالب تصوير أو نسخ:

1. نتيجة `flutter --version`.
2. اسم الجهاز الظاهر في `flutter devices`.
3. صورة التطبيق الافتراضي وهو يعمل.
